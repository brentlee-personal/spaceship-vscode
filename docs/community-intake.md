# 社区参考与采纳记录

先记录用户需要完成的操作，再核对来源和本工程的调用路径。以来源 URL、固定修订和能力为同一条候选的标识。上游有新提交时先看差异，在相同文件或选区上运行最小实验，再更新采纳记录。

| 用户结果                         | 来源与固定修订                                                                                                                                                                 | 本地采用方式                                                                               | 复验操作                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 同一段续写同时受多个维度影响     | [Spaceship 的续写旋钮](https://github.com/chuanqisun/spaceship/blob/4ddd4d1061aa5f22113d5dd03462b3b3e5f506a6/src/text/future-knobs.ts)                                         | 保留旋钮及句子评分，在写作框增加手工输入、推荐和多维调节，将同组指令发送给真实模型         | 从 Markdown 选区打开，配置两个旋钮，检查生成段落和画布上的读数         |
| 保留编辑器的撤销、保存和文件身份 | [VS Code 官方文本编辑器样例](https://github.com/microsoft/vscode-extension-samples/blob/2f83557a56c37a5e48943ea0201e1729708690b6/custom-editor-sample/src/catScratchEditor.ts) | 参考其以 TextDocument 作为文件数据源的设计，采用并排写作面板；确认写回时仅编辑启动时的范围 | 写回后保存并撤销，确认选区两侧的文字完整；修改原文后再次写回应提示冲突 |

在 macOS 的 Microsoft VS Code 1.147.0 中已用临时 Markdown 文件验证了两个维度的真实续写、选区两侧保持完整、保存后磁盘读回、原生撤销、过期写回保护、改名后显示新文件名和从文件夹新建草稿。其他平台欢迎补充验证。

运行 `npm run community:check` 查询两个来源的最新修订。结果仅表示是否需要复查。候选采纳取决于上表的本地工作流实验。
